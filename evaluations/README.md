# Automatic routing qualification

`automatic-v1.json` is a versioned set of 24 hand-labelled synthetic task descriptions covering all 12 workloads. It is a seed for qualification, not evidence of Jev accuracy or savings. Vision, agent and long-document rows explicitly require an image, tools or long corpus before an end-to-end run; a text-only replay cannot qualify those workloads.

Run `python -m evaluations.automatic measurements.json` to score paired measurements. It makes no network calls. Each JSON row must contain the case `id`, `selected_id`, measured `constraint_violations`, `baseline_quality` and `automatic_quality` (0–1, same rubric), end-to-end `baseline_latency_ms` and `automatic_latency_ms`, and `baseline_cost_usd`, `inference_cost_usd`, `decision_cost_usd`. Unknown cost is JSON null and invalidates aggregate savings. Costs include failed attempts; automatic latency includes decision and fallback. Do not substitute routing agreement for answer quality.

For live qualification, use a dedicated Cloud development environment and test provider credentials, explicitly approve provider charges/content sharing, and set a run budget externally. Run each fixture against the frozen general policy and active selection with the same provider catalog snapshot, input and limits. Save outputs outside operational telemetry for rubric review; record model IDs, config hash, provider catalog/price timestamp, catalog/model/instruction versions, token usage, seed and run date alongside measurements. Extend the seed with representative consented workload cases and adversarial/ambiguous inputs. Do not use production traffic or provider secrets in committed fixtures.

Before rollout: zero authorization/constraint violations; review quality regressions by workload, uncertainty and fallback frequency; compare full costs and p95 added latency against an explicitly chosen application budget. Shadow mode measures decision overhead and disagreement only, not counterfactual inference quality or savings. Start with off, then shadow, then a small sample; use the Cloud environment kill switch to return to the frozen general policy. Neither these mock tests nor this seed establishes that automatic routing always wins.
